## Known constraints
- Scanning a large OneDrive via Graph is slow (tens of thousands of items, paged).
  The explorer must scan progressively and cache results with a "last scanned" time.

## Known constraints (dev tooling)
- `npm audit` reports 5 high-sev advisories in a dev-only chain
  (braces→micromatch→fast-glob→@next/eslint-plugin-next), a glob DoS that only affects
  linting. `audit fix --force` would downgrade eslint-config-next, so left as-is.

## Verified live (2026-10-06)
- Connect (3 accounts), overview quota/meters + inline label/description, LAZY explorer
  (surface loads instantly, folders load on open), drill-down, biggest files, stale.
- Cross-account MOVE works via streaming (small file + folder confirmed). It streams
  through this machine — Microsoft has no server-side path for separate personal accounts
  (upload-from-URL 400, share+copy 401; see wiki "Cross-account move"). Move engine is
  resumable (skips done files), auto-retries transient 429/5xx up to 25x, cancellable
  mid-file, with a persistent progress tracker. Source deleted only after full verify.
- Build + tsc + lint clean throughout; server binds 127.0.0.1 only.
