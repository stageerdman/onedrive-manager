# OneDrive Manager — known issues & TODOs

Running list of open items and decisions-to-make. Newest context at the top of
each section. See the INIT update in updates/ for the full build roadmap.

## Blocked on the user (credentials / external setup)
- [ ] Azure app registration not yet created. The app cannot connect any OneDrive
      until AZURE_CLIENT_ID / AZURE_CLIENT_SECRET are filled in .env. Steps are in
      .env comments. Needs: multi-tenant + personal accounts, redirect URI
      http://localhost:3000/api/auth/callback, delegated scopes User.Read +
      Files.Read.All + offline_access.

## Open decisions (to settle in Phase 0/1 of INIT)
- [ ] Persistence store for refresh tokens + usernames/descriptions + scan caches.
      Leaning: local SQLite (better-sqlite3) for a personal app; revisit if deployed
      to Vercel (then a Marketplace store). Tokens always encrypted at rest with
      TOKEN_ENCRYPTION_KEY.
- [ ] "Last used" semantics: Microsoft Graph does not expose true last-accessed for
      personal OneDrive. Analysis will derive staleness from lastModifiedDateTime /
      createdDateTime and must say so in the UI. Confirm this is acceptable.
- [ ] App's own gate: whether the personal app needs any login of its own, or just
      runs locally behind the OS. (UX recommendation pending — see INIT.)
- [ ] Cross-account move (INIT Phase 6): requires upgrading the Azure scope from
      Files.Read.All to Files.ReadWrite.All and re-consenting each account. Graph has no
      native cross-account move — implement as copy → verify → delete-source. Deferred:
      v1 ships read-only analysis first (decided at INIT).

## Known constraints
- Scanning a large OneDrive via Graph is slow (tens of thousands of items, paged).
  The explorer must scan progressively and cache results with a "last scanned" time.
